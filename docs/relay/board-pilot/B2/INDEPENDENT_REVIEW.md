# B2 검수 기록

대상: 단위 B2 "결정 대기열"(`board/`). 날짜: 2026-11-16. 검수자: B1과 같은 하위 에이전트 2명(코드 검수 opus, UI 검수 opus. UI 검수는 ego-browser로 실제 화면을 봤다).

## 1회차

| 검수 | 판정 | 지적 |
|---|---|---|
| 코드 | PASS(필수 수정 0건) | 이번 개선 1건: 선택지 없는 결정의 `'<답>'` 명령을 복사해 그대로 실행하면 "<답>"이 답으로 기록되고 다시 답할 수 없다. 후속 제안: 빈 선택지도 명령이 만들어진다(실행하면 거부된다) |
| UI | FAIL(필수 수정 2건, 이번 개선 1건) | 360px에서 긴 선택지가 넘쳐 가로 스크롤이 생긴다(문서 폭 711px). 선택지 없는 결정의 `<답>` 명령(코드 검수와 같은 결함). 결정 2개가 360px에서 1,300px를 차지한다 |

코드 검수자가 답 10가지(`$(…)`, 역따옴표, `;`, 따옴표 등)로 만든 명령을 임시 저장소에서 실제 셸로 실행했다. 모두 글자 그대로 기록됐고 다른 명령은 실행되지 않았다.

조치: UI 검수 실패를 기록하고 `move B2 build --reason`으로 되돌려 일꾼이 3건을 고쳤다(재위임 1회).

## 2회차 (바뀐 부분만)

| 검수 | 판정 | 지적 |
|---|---|---|
| 코드 | PASS(필수 수정 0건) | 후속 제안: 띄어쓰기가 든 답은 작은따옴표로 감싸야 한다 → 안내 문구에 더했다 |
| UI | PASS(필수 수정 0건, 이번 개선 1건) | 접기 요약 줄에 펼침 표시가 없다 → `▸`·`▾` 표시를 더했다(계획자, CSS 2줄. 다시 검수하지 않았다) |

확인한 것: 360px 가로 스크롤 없음(펼친 뒤에도). 선택지 없는 결정의 명령 글자를 zsh와 bash에 그대로 붙이면 구문 오류로 끝나고 답이 기록되지 않는다(두 검수자가 각각 임시 저장소에서 실행). 결정 구역 높이 360px 기준 1,303px에서 942px로 줄었다.

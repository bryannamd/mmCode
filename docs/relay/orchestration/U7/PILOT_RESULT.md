# U7 시범 결과

날짜: 2026-11-16. 시범 계획: `docs/relay/board-pilot/PLAN.md`(단위 B1 단위 보드, B2 결정 대기열, B3 열린 지시). 산출물: `board/`(정적 화면, 시험 21개). 커밋: B1 `2a88eb5`, B2 `6a737a7`, B3 `6cac2db`.

진행 방식: relay 수동 모드. 계획자(이 세션) 1명, 일꾼(claude sonnet 하위 에이전트) 1명, 검수자 2명(코드 검수, UI 검수. 둘 다 claude opus 하위 에이전트, UI 검수는 ego-browser로 실제 화면을 봤다). 단계와 증거는 모두 `phase.sh`로 기록했다.

## 확인 항목 6개 (계획 9절)

| 번호 | 항목 | 결과 | 근거 |
|---|---|---|---|
| 1 | 단위 하나를 완료한 뒤 다음 단위로 넘어간다 | 통과 | B1 → B2 → B3. 각 단위의 `move … build`는 선행 단위가 `done`이 된 뒤에만 됐다 |
| 2 | UI 결함을 수정한 뒤 해당 부분만 다시 검수한다 | 통과 | 세 단위 모두 UI 검수에서 결함이 나왔다(B1 4건, B2 필수 2건, B3 필수 1건). `move … build --reason`으로 되돌려 고치고 바뀐 부분만 재검수해 통과했다 |
| 3 | 단위 후 정지가 다음 단위 시작을 막는다 | 통과 | B1 완료 뒤 `direct stop-after`(I1). 새 세션 역할 에이전트의 `move B2 build`가 `REFUSED: 단위 후 정지 지시 I1 가 열려 있다. B2 을 시작하지 않는다.`로 거부됐다. 에이전트는 우회하지 않고 사용자에게 `direct resume`을 요청했다 |
| 4 | 열린 지시가 세션 교체 뒤에도 남는다 | 통과 | 인계 문서만 받은 깨끗한 맥락의 에이전트가 `phase.sh show`에서 I1을 읽었다 |
| 5 | 세션 교체 뒤 중복 실행 없이 재개한다 | 통과 | 그 에이전트는 끝난 B1을 다시 하지 않고 B2로 갔다. B1의 `done` 이벤트는 1건이다 |
| 6 | 필요한 검사를 실행하지 않았거나 실패한 단위가 완료로 표시되지 않는다 | 통과 | B1: UI 검수 실패를 기록하자 `REFUSED: B1 에 빠진 증거: mutation, ui-review`. B3: 재작업으로 이전 회차의 검수 기록이 무효가 되어 `REFUSED: B3 에 빠진 증거: review, mutation` |

## 시범에서 드러난 것

1. 실패 먼저 기록이 명령 오류로 통과했다. B1의 첫 `fail-first`는 `node --test board/`가 node 24에서 폴더를 읽지 못해 실패한 것이었다. `phase.sh`는 종료 코드만 본다. 계획자가 로그를 열어 발견했고, 빈 구현으로 다시 돌려 단언 실패를 확인한 뒤 다시 기록했다. 이후 브리프에 "로그를 열어 실패 이유가 단언 실패인지 확인한다"를 넣었다. 후속: 계획자와 검수자의 확인 항목에 넣는다(코드로 강제하지 않는다).
2. UI 검수가 시험이 잡지 못한 결함을 찾았다. 360px 가로 스크롤, 첫 화면 밖으로 밀린 정지 띠, 되돌릴 수 없는 `<답>` 명령. 앞의 둘은 node 시험으로는 잡을 수 없다.
3. 코드 검수와 UI 검수가 다른 방법으로 같은 결함(선택지 없는 결정의 `<답>` 명령)을 찾았다.
4. 재작업 뒤에는 이전 회차의 검수 기록이 효력을 잃어 다시 받아야 했다. 의도한 동작이다. 계획자가 HTML 2줄만 고친 B3는 코드 재검수 없이 UI 재검수로 대신했고 그 사실을 검수 기록에 적었다.
5. 깨끗한 맥락의 재개 에이전트가 문서의 빈 곳을 짚었다(열린 정지 지시가 있을 때 무엇을 보고하는지). resume 절에 한 줄을 더했다.
6. 실행 중 사용자 결정이 필요한 판단 2건을 교차 검토로 정했다: U7 시범 대상(D1, 3명 모두 같은 답), U6 검수 회차 상한 초과(D4, 2대 1).

## 하지 않은 것

- relay `auto`(단위 자동)를 실제 계획으로 돌려 보지 않았다. 시범은 수동 모드였다. U6의 auto 연결은 `eval-goal.sh` 시험 216개로만 확인했다.
- 실제 세션 교체(`rotate.sh`로 새 Herdr 터미널 띄우기)를 하지 않았다. 세션 교체는 인계 문서만 받은 새 하위 에이전트로 흉내 냈다.
- `gate`를 도구 호출 전 훅으로 등록하지 않았다(사용자 설정 변경. 결정 대기 항목). 즉시 중단은 `gate` 명령의 종료 코드로만 확인했다.
- 사용자의 실제 프로젝트에서 하는 시범은 하지 않았다(사용자가 대상을 고른 뒤에 한다).

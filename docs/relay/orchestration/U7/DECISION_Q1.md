# 결정 요청 Q1: U7 시범을 어디에서 할 것인가

작성: 2026-11-16, 계획자. 이 문서는 교차 검토자에게 주는 질문이다. 계획자의 추천안은 적지 않았다.

## 배경

- 계획: `docs/plans/orchestration-plan.md`. U7은 9절 표의 마지막 단위다("실제 기능 3개 안팎으로 시범"). 확인 항목 6개는 같은 절의 "U7 확인 항목"에 있다.
- 확인 항목 2번은 UI 결함을 고친 뒤 그 부분만 다시 검수하는 것이다. 그래서 시범 대상에는 화면이 있어야 한다.
- 권한 경계(7.1절): 계획의 작업 폴더(이 저장소) 밖에 쓰는 일은 사용자의 결정을 기다려야 한다. 교차 검토로 넘을 수 없다.
- 사용자는 지금 자리에 없다. 사용자의 지시: U7까지 멈추지 않는다. 사전 계획에 없는 결정은 다른 종류의 에이전트 2종 이상의 교차 검토로 정한다.
- 12절 "정해야 할 것"에 이 질문이 남아 있다.

## 선택지

- 가: 이 저장소의 모니터 앱(`monitor/`, Swift)에서 한다. 남은 기능은 `docs/plans/monitor-plan.md` 6절 "아직 없는 것"에 있다(지시 보내기, 결정 답 보내기 등). 이 앱은 다른 세션이 맡아 만들고 있다. 그 세션과 같은 파일을 고치게 된다.
- 나: 이 저장소 안에 작은 화면을 새로 만든다. 예: 이벤트 파일 `.mmcode/events.jsonl`을 읽어 단위별 단계와 결정 대기열을 보여 주는 정적 HTML 페이지. 기능 3개를 단위 3개로 나눈다. 다른 세션의 파일과 겹치지 않는다. 모니터 앱과 역할이 일부 겹친다.
- 다: 시범 대상을 정하지 않는다. U7만 막힘으로 두고, 사용자가 돌아와 실제 프로젝트를 고른다. U1~U6은 끝낸다.

## 답하는 형식

아래 형식으로 결과 파일에 쓴다. 다른 내용은 쓰지 않는다.

```
선택: 가 | 나 | 다
근거:
- <파일 경로>:<줄 번호> <그 줄이 뒷받침하는 내용 한 문장>
- (2개 이상)
위험: <이 선택의 가장 큰 위험 한 문장>
되돌리는 방법: <한 문장>
```

근거는 이 저장소의 파일과 줄 번호로만 든다. 파일을 고치지 않는다. 명령을 실행하지 않는다.

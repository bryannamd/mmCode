# mmCode 프로젝트 모니터 계획

작성일: 2026-11-15
상태: 화면 시안 완성(2026-11-15, 방향은 "단면도 그림책"). 앱 첫 판 구현(2026-11-16, 6절). 결정 답과 지시 보내기 포함.
상위 계획: `docs/plans/orchestration-plan.md`(실행 체계 전체). 이 문서는 모니터 앱의 정본이다.
제품 기록: `PRODUCT.md`. 시안: `docs/plans/monitor-office-mock.html`.

데이터 층(이벤트 파일, 세션 대화 파일 읽기)의 정의는 상위 계획 4절에 있다. 낱말, 단계, 멈춤 분류, 지시, 증거 종류는 상위 계획 3절을 그대로 쓴다. 메뉴 막대에서 여는 창은 화면 용어로 "패널"이라고 부른다. 이 문서는 그 정의를 바꾸지 않는다. 바꿀 필요가 생기면 상위 계획 담당 세션에 알린다.

## 모니터 앱

### 1. 범위와 형태

- 형태: macOS 네이티브 앱(Swift/AppKit, 2026-11-15 사용자 확정). 앱 인스턴스는 하나다. 평소에는 메뉴 막대 아이콘만 있다. 클릭하면 패널이 뜨고, 바깥을 클릭하면 닫힌다.
- 패널 크기는 480×300이다(2026-11-15 사용자 확정). 보기는 세 가지다.
  1. 건물(개요): 모든 프로젝트를 층 하나씩 보여 준다.
  2. 사무실(상세): 건물에서 고른 프로젝트 하나의 에이전트, 단위, 결정 대기열, 증거를 보여 주고 지시를 받는다.
  3. 목록: 지금 보는 프로젝트의 같은 정보를 글자로 보여 준다.
- 프로젝트 목록은 `hc ls`의 터미널 작업 폴더를 git 저장소 루트로 묶어서 만든다. 등록 파일을 따로 두지 않는다.
- `.mmcode/events.jsonl`이 없는 프로젝트는 개요에 `hc` 정보만 표시한다. 상세 화면은 터미널 목록과 상태 문구까지만 보여 준다.
- 알림: 결정 대기나 환경·한도로 멈추면 macOS 알림을 보낸다. 알림을 클릭하면 그 프로젝트의 상세 화면이 열린다.
- 웹뷰를 쓰지 않는다(Tauri·Electron 제외).

### 2. 화면: 가상 사무실

표가 아니라 공간으로 현황을 읽는다. 움직이는 시안: `docs/plans/monitor-office-mock.html`(2026-11-15, 예시 데이터). 디자인 기준은 `DESIGN.md`에 있다.

패널 구성(위에서 아래로):

| 영역 | 크기 | 내용 |
|---|---|---|
| 지붕 | 28px | 건물 버튼, 프로젝트 이름, 상자 진행 칸과 완료 수, 다른 층의 알림, 목록 버튼 |
| 장면 | 480×216 | 사무실 또는 건물의 단면. 논리 해상도 240×108을 2배로 확대한다 |
| 지반 | 56px | 지금 보는 층에서 사용자가 나설 일 한 줄과 버튼 |

- 패널 틀이 건물의 단면이다. 지붕과 지반은 낮과 밤에 같은 남색이고, 장면의 색만 바뀐다.
- 지반은 평소에 남색이다. 상태 한 문장과 단위 후 정지, 즉시 중단 버튼이 있다.
- 결정 대기나 단위 막힘이 있으면 지반이 분홍으로 바뀐다. 묻는 캐릭터의 얼굴, 질문, 답 버튼이 나온다. 분홍은 "당신 차례"에만 쓴다.
- 같은 사실을 두 번 적지 않는다. 지붕은 다른 층의 알림만, 지반은 지금 보는 층의 일만 말한다.
- 주의 표시(물음표, 느낌표, 분홍 벨)는 장면 위의 별도 층에 그린다.

개요(건물):

- 건물 단면도를 보여 준다. 층 하나가 프로젝트 하나다.
- 층의 위치는 바꾸지 않는다. 사용자가 위치로 프로젝트를 기억하기 때문이다.
- 층마다 이름표, 상자 진행 칸, 캐릭터가 보인다. 캐릭터의 크기는 사무실 보기와 같다. 에이전트가 없는 층은 어둡다. 에이전트가 있었던 적도 없고 기록도 없는 프로젝트(셸만 있는 곳)는 층으로 넣지 않는다.
- 지반은 모든 층 중에서 가장 급한 일 하나를 말한다.
- 주의가 필요한 층은 층 옆의 등이 분홍으로 켜진다. 깜박이지 않고 1px 위아래로 움직인다. 결정 대기는 물음표, 단위 막힘과 환경·한도는 느낌표 모양이다. 색만으로 구분하지 않는다.
- 층을 클릭하면 그 프로젝트의 사무실로 들어간다.

상세(사무실, 프로젝트 하나):

단계는 다섯 개다(상위 계획 3.2절). 장소가 단계다. 필드 이름은 `phase`다.

| 단계 | 기계 값 | 장소 | 보이는 것 |
|---|---|---|---|
| 대기 | `queued` | 왼쪽 선반 | 대기 중인 단위 |
| 구현 | `build` | 책상 | 모니터가 켜지면 도구를 쓰는 중 |
| 검증 | `verify` | 시험대 | 등이 노랑이면 실행 중, 초록이면 통과, 빨강이면 실패 |
| 검수 | `review` | 벽 화면 | 독립 검수와 UI 검수 |
| 완료 | `done` | 오른쪽 선반 | 커밋 기록이 있는 단위 |

멈춤은 단계와 따로 표시한다(상위 계획 3.3절). 단위가 어느 단계에 있든 멈출 수 있다.

| 멈춤 분류 | 표시 |
|---|---|
| 결정 대기 | 호출 벨, 분홍 |
| 사용자 정지(단위 후 정지, 즉시 중단) | 문 옆 표지판 |
| 단위 막힘 | 상자에 오류 표시(느낌표) |
| 환경·한도 | 사무실 오류 표시(느낌표) |

그 밖의 장소: 소파는 할 일이 없는 에이전트의 자리다. 문은 일꾼이 시작하고 종료하는 곳이다.

- 단위는 상자다. ID는 `U<번호>`다. 상자가 놓인 자리가 단계이고, 상자를 든 캐릭터가 담당자다.
- 캐릭터나 상자를 클릭하면 지반에 요약 한 줄이 나온다. 캐릭터는 이름, 모델, 상태, 지금 하는 일이고 상자는 단계와 가장 최근 증거다.
- 전체 내용은 목록 보기에 있다: 최근 행동 목록, 터미널 화면 끝부분(`hc read`), 완료 기준, 종류별 증거와 증거 경로, 받은 지시와 적용 상태, 커밋.
- 증거는 `check.result` 이벤트다(상위 계획 3.4절). 종류는 검사 명령(`cmd`), 실제 확인(`manual`), 실패 먼저(`fail-first`), 독립 검수(`review`), 변형 점검(`mutation`), 교차 검토(`cross-review`), 커버리지(`coverage`), UI 검수(`ui-review`)다. 상자의 상세에 종류별 결과를 보여 준다.
- 같은 정보를 글자 목록으로도 제공한다. 키보드 사용자와 좁은 화면을 위해서다.

장면 규칙:

1. 움직임은 실제 이벤트가 있을 때만 만든다. 일하는 것처럼 보이게 하는 무작위 움직임을 넣지 않는다.
2. 움직이는 것은 모두 정보다. 장식은 움직이지 않는다.
3. 개입이 필요한지는 1초 안에 읽힌다. 담당자와 막힌 위치는 3초 안에 읽힌다.
4. 이벤트가 몰리면 중간 동작을 건너뛰고 최신 상태로 맞춘다.
5. 수명이 짧은 하위 에이전트는 최소 표시 시간을 두어 깜박이지 않게 한다.

### 3. 캐릭터

- 하네스마다 동물 하나다(2026-11-15 사용자 확정): 고양이 claude-code, 개 codex, 개구리 agy.
- 털 무늬가 모델이다. 머리띠는 쓰지 않는다. 색만으로 구분하지 않도록 무늬를 다르게 한다.
  - 고양이: fable 턱시도, opus 삼색, sonnet 치즈 태비, haiku 흰색. 모르는 모델은 회색 민무늬다.
  - 개(시안): 기본 모델 비글(황갈색 얼굴, 흰 콧등 줄), 가벼운 모델 점박이(흰 얼굴, 한쪽 눈의 회색 얼룩). 귀가 아래로 늘어진다.
  - 개구리(시안): 기본 모델 민무늬, 가벼운 모델 점박이. 눈이 머리 위로 튀어나온다.
- 역할(계획자, 일꾼, 검수자)은 이름과 자리로 읽는다. 역할 소품은 두지 않는다.
- effort는 상세에 글자로 표시한다.
- 동작은 상태다: 타자(작업), 걷기(이동), 손들기(결정 대기), 졸기(휴식), 멈춤 표시(사용자 정지), 느낌표(단위 막힘, 환경·한도).
- 말풍선에는 지금 쓰는 도구와 대상을 한 줄로 적는다. 상태가 바뀐 직후에만 잠깐 보인다. 한 번에 하나만 보이고 상자를 가리지 않는다. 평소에는 머리 위의 작은 그림 표시만 있다.
- 주의 상태(결정 대기, 단위 막힘, 환경·한도, 사용자 정지)에는 말풍선을 쓰지 않는다. 픽셀 표시만 쓰고 글은 지반에 적는다.
- 상태는 색만으로 구분하지 않는다. 글자를 함께 표시한다.
- 그림은 직접 만든다. 약 12×16 크기의 스프라이트를 보간 없이 2배로 확대한다.

선행 사례: Pixel Agents(VS Code 확장, `github.com/pablodelucca/pixel-agents`)가 Claude Code 세션을 사무실의 픽셀 캐릭터로 보여 준다. 세션 대화 파일을 읽는 방식이다. 이 계획이 더하는 것은 단계와 장소의 대응, 결정 대기열, 클릭 개입, 여러 프로젝트 개요, 네이티브 앱이다. 그 프로젝트의 가구 그림은 따로 구매해야 하는 타일셋이므로 가져오지 않는다.

### 4. 개입

| 클릭 대상 | 동작 | 전달 방법 |
|---|---|---|
| 캐릭터 | 최근 행동 보기, 메시지 보내기 | 지시 `message`. 계획자는 `hc send`. 하위 에이전트는 계획자를 거친다 |
| 상자 | 완료 기준과 종류별 증거 보기, 순서 변경 | 지시 `reorder` |
| 결정 | 추천안 수락 또는 직접 입력 | `decision.answer` 이벤트 + `hc send` |
| 단위 후 정지 | 지금 단위가 끝난 뒤 다음 단위를 시작하지 않는다 | 지시 `stop-after` |
| 즉시 중단 | 바로 멈춘다. 확인을 1회 받는다 | 지시 `interrupt` + `hc interrupt` |
| 계속 | 사용자 정지를 푼다 | 지시 `resume` |

- 종료(kill) 버튼은 두지 않는다. 미완료 변경을 자동으로 지우지 않는다.
- 별도 제어 파일은 없다. 지시는 `directive.received`, `directive.applied`, `directive.rejected` 이벤트로 쓴다(상위 계획 4.1·4.4절). 화면에는 접수, 적용됨, 거부됨으로 표시한다. 적용하다가 사용자의 판단이 필요하면 거부됨으로 표시하고 결정 요청을 따로 올린다.
- 순서 변경은 다음 단위부터 적용한다. 진행 중인 단위를 버리지 않는다.
- 결정 대기열의 항목에는 질문, 추천안, 영향, 막힌 단위, 그동안 가능한 작업을 표시한다.
- 세션이 바뀌어도 미처리 지시와 승인 범위가 남는다.

### 5. 자원 기준

1. 패널이 닫혀 있으면 그리지 않는다.
2. 움직임은 `CALayer` 프레임 전환으로 처리한다. 2~4fps로 제한하고, 창이 가려지면 멈춘다.
3. 폴링하지 않는다. `hc events` 출력과 이벤트 파일 변경 알림을 받을 때만 깨어난다. 건물 보기도 층마다 이벤트 파일에서 계획 상태를 읽는다. 크기나 수정 시각이 바뀐 파일만 다시 읽는다. 기록 폴더(`.mmcode`)가 있는 층의 이벤트 파일은 모두 지켜본다(2026-11-16 변경. 프로젝트별 요약 값을 주는 곳이 아직 없고, 다른 층의 결정 대기를 바로 알려야 한다).
4. 합격 기준: 메모리 35MB 이하, 닫힌 상태 CPU 0.1% 이하, 열린 상태 한 코어의 1% 이하. 메모리는 실제 메모리(`task_info`의 phys_footprint)로 판정한다(2026-11-16 사용자 결정). `ps -o rss`는 공유 라이브러리 페이지가 들어가서 쓰지 않는다. CPU는 `ps -o %cpu`로 잰다.
5. 참고 측정값: `herdr-core` 0.1.21은 터미널 34개를 관리하면서 메모리 약 13MB, CPU 0.0%다(2026-11-15 `ps` 실행 결과).

메모리 35MB는 최소 AppKit 앱의 일반적인 범위에서 잡은 목표다. 이 앱의 측정값이 아니다. 기준을 넘으면 Rust와 직접 그리기 방식으로 바꾸는 것을 검토한다.

### 6. 구현 상태 (2026-11-16)

코드는 `monitor/`에 있다(Swift 패키지). 쓰는 길은 relay의 `phase.sh answer`·`phase.sh direct`와 `hc send`·`hc keys`다(`hc` 쓰기는 2026-11-17에 더했다).

| 대상 | 내용 |
|---|---|
| `MonitorCore` | 자료 모델(`Model.swift`), 기록 읽기(`EventLog`), `hc` 읽기(`HcClient`), 프로젝트 묶기(`ProjectGrouping`), 층 순서(`FloorOrder`), 파일 변경 알림(`FileWatcher`) |
| `MonitorScene` | 상태를 장면으로 바꾸기(`SceneBuilder`), 픽셀 그리기(`SceneRenderer`, 시안의 값 그대로), 예시 자료(`Demo`) |
| `mmcode-monitor` | 메뉴 막대 앱. 패널 240×180pt, 지붕, 장면, 지반, 목록 |
| `scene-snap` | 장면을 PNG로 저장하는 확인 도구 |

실행:

- 빌드와 시험: `cd monitor && swift build && swift test`
- 실행: `swift run -c release mmcode-monitor`. 메뉴 막대의 얼굴 아이콘을 클릭한다. 오른쪽 클릭 메뉴에 종료가 있다.
- 예시 자료: `--demo quiet|decision|blocked|stopped|building|otherFloorAlert|question`
- 패널을 PNG로 저장: `--snapshot <경로> [--view office|building|list] [--day|--night] [--select actor[:번호]|box] [--press <지반 버튼 이름>]`
- 측정: `--exit-after <초> [--open]`. 끝날 때 메모리 값을 한 줄로 적는다.

된 것:

- `hc events`의 변화나 기록 파일의 변경이 올 때만 `hc ls`를 다시 읽는다. 폴링하지 않는다.
- 기록 폴더(`.mmcode`)가 있는 모든 층의 `.mmcode/events.jsonl`을 지켜본다. 단계가 장소로, 멈춤이 표시로 보인다. 다른 층의 멈춤도 기록이 바뀌면 바로 반영된다.
- 건물, 사무실, 목록 보기. 캐릭터와 상자를 클릭하면 지반에 요약이 나온다.

- `hc` 명령 경계(2026-11-17 변경): 읽기는 `ls`, `get`, `events`, `read`다. 쓰기는 `send`와 `keys` 두 개만 `HcClient.write`로 허용한다. 주소가 `-`로 시작하면 거부한다. `keys`는 숫자 1~9 하나만 받는다. 사용자 글은 셸을 거치지 않고 `--` 뒤 인자 한 칸으로 넘긴다. `send --force`, `kill`, `rm`, `run`은 코드에 없다. 예시 자료와 `--snapshot`에서는 실행하지 않는다.
- 메시지 보내기(2026-11-17): 입력칸에서 보내면 `hc send <주소> -- <글>`을 실행한다. `HC_TERMINAL_ID`를 뺀 환경이라 받는 세션은 사용자 입력으로 받는다. `phase.sh` 기록은 하지 않는다. `--force`를 쓰지 않으므로 질문 창에는 답하지 않는다. 시간 제한은 70초다(hc가 사용자의 미완성 입력을 최대 60초 기다린다).

- 객관식 질문 답하기(2026-11-17): 사무실로 보는 층에서 `hc get`의 `status.kind`가 `question`이고 blocked인 터미널만 화면(`hc read --lines 0`)을 읽는다. `QuestionScreen.parse`가 질문과 선택지를 뽑는다("Type something.", "Chat about this"는 뺀다). 지반 또는 그 캐릭터를 고른 지반에 선택지 버튼이 나온다. 누르면 화면을 다시 읽어 같은 질문·같은 선택지일 때만 `hc keys <주소> <번호>`를 보낸다. 다르면 "질문이 바뀌었습니다. 다시 보세요"라고 알린다. 질문 탭 여러 개와 multiSelect는 따로 다루지 않는다(다음 갱신에서 다음 화면을 다시 읽는다).

  - 결정은 선택지를 버튼으로 보인다. 지반에 다 들어가지 않으면 앞의 몇 개와 "다르게 답하기"를 둔다. "다르게 답하기"와 "메시지"는 지반 안의 입력칸을 연다.

  - 결정 요청 기록 없이 멈춤만 있으면 답할 ID가 없다. 이때는 "터미널 <주소>에서 답하세요"라고 안내한다.

시안과 다르게 정한 것(2026-11-16 사용자 확정):

1. 층이 4개보다 많으면 스크롤 휠이나 화살표 키로 넘긴다. 위아래에 작은 화살표가 보인다.
2. `hc` 상태가 `blocked`(입력을 기다림)인 터미널은 손을 들고, 지반이 분홍으로 바뀐다. `error`는 환경·한도로 표시한다. 입력 대기의 분홍은 사용자가 확인했고(2026-11-16) `DESIGN.md`에 넣었다.
3. 사용자 정지 때는 쉬던 담당자도 모두 멈춤 표시를 한다. `hc` 상태로는 누가 멈춘 것인지 구별할 수 없다.
4. 환경·한도의 사무실 표시는 문 위의 분홍 느낌표다. `DESIGN.md`의 주의 표시 절에 넣었다.
5. 결정 버튼은 기록의 선택지다. 선택지가 없으면 추천안과 "다르게 답하기"다.
6. 가벼운 모델 판정은 추정이다: codex는 모델 이름에 `mini`나 `nano`, agy는 `flash`나 `lite`.
7. 탭 이름이 숫자뿐이면 스페이스 이름을 앞에 붙인다. 말풍선은 18자에서 자른다.

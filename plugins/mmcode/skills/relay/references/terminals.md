# Herdr 터미널: 패널 수와 숨긴 터미널

Herdr 안(`HC_TERMINAL_ID`가 있음)에서 `hc run`으로 일꾼·검토자·스크립트를 띄울 때 따른다. relay·pair·plan 교차 검토가 함께 쓴다. 근거는 `docs/review/2026-11-18-hidden-terminals.md`다. 2절 표에서 스크립트 열 전부와 에이전트의 입력 대기·kill·부모 종료는 직접 실행해 확인했다. 에이전트의 정상·실패 종료 알림은 확인하지 않았다(에이전트는 보통 끝나지 않고 `idle`·`done` 상태로 남는다). 3·4절의 `hc attach`·`< /dev/null`·알림 끄기는 `hc` 도움말로만 확인했다.

## 1. 패널은 내가 띄운 것 3개까지

- `hc run`에 `--label herdr.space=<값> --label herdr.tab=<값>`을 붙이면 내 탭에 패널로 뜬다. 값은 `hc get "$HC_TERMINAL_ID"`의 `labels`에서 읽는다.
- 세는 법: `hc ls --label herdr.tab=<내 탭>`에서 `parent`가 내 주소이고 살아 있는 터미널 수 + 이번에 함께 띄울 수. 내 메인 패널과 남의 패널은 세지 않는다. 화면에는 내 메인 패널을 합쳐 4개까지 보인다(2026-11-18 사용자 지시: "3개 정도까지 패널이 열리는 것은 괜찮다").
- 합이 3을 넘으면 이번에 띄울 것은 전부 라벨 없이 숨긴다.
- 숨긴 직후 `숨겨서 N개 실행: <이름들>`을 한 줄로 알린다.
- `--no-parent`로 띄우는 것(relay 세션 교체)은 내 세션이 끝나도 남는다. 숨기지 않는다.

## 2. 숨긴 터미널에서 일어나는 일

| 상황 | 에이전트(claude·codex·agy) | 스크립트(bash 등) |
|---|---|---|
| 정상 종료 | 부모에게 `<hc>… exited (exit 0)</hc>` 알림 | 같다. 마지막 출력 줄도 온다 |
| 실패 종료 | `exit N`이 알림에 그대로 온다 | 같다 |
| 입력·승인·로그인 대기 | `hc wait`가 바로 `blocked`와 사유(`hc get`의 `status.kind`·`status.msg`)를 돌려준다. 부모에게 알림도 온다 | **보고하지 않는다.** `hc wait`는 `timeout`만 돌려준다 |
| 내가 `hc kill` | 알림 없음(`signal`만 남음) | 같다 |
| 부모 세션 종료 | 함께 끝난다(`die_with_parent: true` 기본값) | 같다 |

## 3. 감시와 회수

알림은 보조 수단이다. 알림은 꺼져 있을 수 있고(`hc run --no-notify`, 설정 `notes = false`) 늦게 올 수 있다. 상태는 항상 제한 시간 대기로 회수한다.

1. 기다릴 때는 `hc wait <주소> --timeout <초>`를 쓴다. 돌아오면 `reason`을 본다.
   - `message`: 나에게 다른 메시지가 와서 풀린 것이다. 그 메시지를 처리하고, 끝나지 않은 터미널마다 같은 대기를 다시 건다.
   - `timeout`·`blocked`·`error`: `hc read <주소>`로 화면을 본다. 스크립트는 이것이 유일한 감시다. 화면이 입력 프롬프트면 4절로 간다.
2. `hc run`이나 `hc send`의 결과에서 `first_message.sent`가 false이면 첫 지시가 전달되지 않은 것이다. 막힌 원인(신뢰 창 등)이 풀린 뒤 `hc send --wait`로 지시를 다시 보내고, `started`가 true인지 본 뒤 대기를 다시 건다.
3. 스크립트는 되도록 입력을 받지 않게 띄운다(비대화형 옵션, `… < /dev/null`). 이것이 실패 종료를 보장하지는 않는다(`/dev/tty`에서 읽는 프로그램이 있다). 1번의 제한 시간 감시는 그대로 한다.
4. 끝났는지는 알림 하나로 정하지 않는다. `hc get`의 `state`·`exit_code`와 결과 파일을 함께 본다.
5. 정리: 끝난 것은 `hc rm`, 아직 살아 있으면 `hc kill` 뒤 `hc rm`. 내가 띄운 것만 정리한다.

## 4. 사용자 입력이 필요할 때

에이전트가 대신 입력하거나 승인하지 않는다(폴더 신뢰·로그인·권한 승인 모두).

1. 사유를 정한다. 에이전트는 `hc get`의 `status.msg`, 스크립트는 `hc read` 화면의 마지막 프롬프트 한 줄이다.
2. 내 패널이 3개 미만이면 `hc label <주소> herdr.space=<값> herdr.tab=<값>`으로 꺼낸다. 패널이 바로 나타난다(직접 확인). 꺼낸 패널은 라벨을 지워도 다시 숨겨지지 않는다. 그 터미널이 끝나 정리될 때 사라진다.
3. 이미 3개면 꺼내지 않는다. 사용자에게 "다른 터미널 창에서 `hc attach <주소>`로 들어가 처리하고 `ctrl+\`로 빠져나온다"고 안내한다. 대화 입력창의 `!` 명령으로는 들어갈 수 없다. 빠져나와도 그 터미널은 계속 돈다.
4. 주소·이름·사유를 한 줄로 알린다. 그 터미널은 사용자가 처리할 때까지 기다리고, 다른 독립 작업은 계속한다.
5. 사용자가 처리했다고 하면 3절 1번 대기를 다시 걸고, 필요하면 3절 2번으로 지시를 다시 보낸다.
6. 사용자가 취소하라고 하면 `hc read`로 마지막 화면을 남긴 뒤 `hc kill`·`hc rm`으로 닫는다. 첫 지시가 전달되기 전이면 `미실행 · 사용자 취소`, 그 뒤면 `중단 · 사용자 취소`로 보고하고 이미 바뀐 파일이 있는지 확인한다.

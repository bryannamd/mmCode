# relay 고정 규칙 (범용판)

| # | 규칙 | 이유 |
|---|---|---|
| R1 | 다른 저장소를 만져야 하면 `.claude/settings.json` `permissions.additionalDirectories` 에 등록하고 Worker 가 직접 편집한다. stage/manifest/apply 복사 절차를 만들지 않는다. 등록은 인계 문서 "종료 시 제거" 절에 기록 | 이전 계획에서 stage/apply 가 단위당 가장 큰 낭비였음 |
| R2 | 검증 1회. Worker 가 실행한 로그를 Advisor 가 읽고 diff 만 검토. 검수자는 diff + 신규 테스트만 실행. 무거운 통합 테스트는 2~3단위마다 1회(단위 끝 `run_in_background`). lint 는 pathspec 파일만(`eslint <files>`), 전체 lint·기준선 비교 로그 금지 | 실행 3회 → 1회. 전체 lint 로그는 회당 600KB+ |
| R3 | 검수 티어: 순수 모듈·테스트 = sonnet(`/code-review low` 대체 가능), 저장 트랜잭션·권한 경계·lease·동시성 = opus. 적대 프로브는 opus 검수에서만 | 검수 비용 절반 이하 |
| R4 | 단위 크기: 브리프 1 → Worker 1 → 검수 1 → 커밋 1. 인계 문서는 단위 끝에 상태표 한 행만 갱신 | 의식 횟수 절반 |
| R5 | Worker 티어는 plan 3절 표를 따른다. 같은 탭에 codex 가 있으면 순수 모듈은 codex(`pair`) | 토큰 단가 |
| R6 | 병렬은 서로 다른 파일의 순수 모듈만. 같은 파일 체인은 직렬. 병렬 편집은 `isolation: worktree` 또는 별도 파일 | 충돌 회피, 병렬은 시간만 줄이고 토큰은 안 줄임 |
| R7 | 직전 단위의 Worker 또는 검수가 opus 였거나 세션에서 2단위를 마쳤을 때만 세션 교체. sonnet/haiku 단위 뒤에는 이어서 진행. 세션당 최대 2단위 | 교체 1회 ≈ 10분. 09-16 계획에서 세션 11개/단위 10개 |
| R8 | 300줄 넘는 파일은 `cat` 금지(`grep`/`sed -n`). 조사·1~2파일 수정·diff 검수는 압축 출력 에이전트(caveman 플러그인의 cavecrew 가 있으면 그것, 없으면 일반 하위 에이전트) | 메인 컨텍스트 유입 감소 |
| R9 | 푸시·배포·활성화·승인 파일·외부 전송은 항상 사용자 확인. 커밋은 인계 문서 정책 줄이 정한다(기본 확인 후) | Git 안전 규칙 |
| R10 | 저장소가 둘 이상이면 단위 표 pathspec 열에 저장소별로 적고, 커밋도 저장소별로. 다른 세션의 `.gitignore`·정책 변경으로 미추적이 되면 이월 항목에 기록 | 이전 계획에서 테스트 파일이 조용히 미추적됨 |
| R11 | 다중 세션 흔적(`git status --short` 에 내 것 아닌 변경)이 있으면 diff 는 `git diff HEAD -- <path>`, 커밋은 `scripts/commit-unit.sh` 2단계 — `prepare <repo> <msg-file> <path>...`(임시 인덱스에 `read-tree HEAD` → 내 경로만 add → `write-tree` → `diff --stat` 출력 후 멈춤) → 사람이 stat 을 읽고 내 파일만인지 확인 → `finish <repo>`(`commit-tree -p OLD` → `update-ref <new> <old>`, old 가 다르면 실패 → 공유 인덱스 `reset -q -- <paths>`). 함정: ① 같은 파일에 남의 hunk 가 섞이면 내 hunk 만 패치로 뽑아 **HEAD 기준** blob 에 적용한다(인덱스의 낡은 blob 에 적용하면 남의 커밋을 되돌린다) ② `git add` 뒤 남의 커밋으로 HEAD 가 움직이면 내 인덱스 blob 이 낡아 남의 변경을 되돌리는 hunk 가 생긴다 — 커밋 직전 `git log -1` 로 HEAD 를 다시 확인한다 ③ 임시 인덱스로 커밋한 신규 파일은 공유 인덱스에 없어 `D `(삭제)로 보인다 — finish 의 `reset -q -- <paths>` 가 그래서 필요하다 ④ 검증과 커밋을 한 호출로 묶지 않는다(출력에 남의 파일이 보여도 이미 커밋된 뒤다) ⑤ `git stash`·`reset --hard` 금지 | 공유 인덱스 오염 |
| R12 | 문서 분량 상한: BRIEF 8KB(정본은 절 번호 인용) · REPORT 표 3개 + 400단어 · INDEPENDENT_REVIEW 판정·발견 표·실행 명령만 · 인계 문서 이월 항목당 한 줄 120자, 해소 즉시 삭제, 막지 않는 minor 는 `DEBT.md` | 09-16 계획 REPORT 1,000~5,300단어·검수서 700~3,500단어, 다음 세션은 읽지 않는 문서 |
| R13 | **auto 완료 조건.** ① 문법: 재개 블록 `완료 조건:` 아래 `cmd: <명령>` 줄(여러 개)과 `timeout: 10m`(`cmd:` 하나의 제한 시간, 생략하면 10m). `cmd:` 한 줄은 단순 명령 하나이고, 따옴표 밖 `#`부터 줄 끝까지는 주석이다(`shlex.split(..., comments=True)`, 따옴표 안 `#`는 인자로 남는다). ② 거부(`eval-goal.sh check`가 항목마다 PASS/FAIL을 찍고 `init`도 먼저 같은 검사를 한다): 셸 메타문자(`;` `\|` `&` `` ` `` `$` `(` `)` `<` `>`)·글로빙 문자(`*` `?` `[`)·환경변수 접두사(`FOO=bar cmd`)·외부 전송/삭제/푸시/권한 상승 패턴(`curl` `wget` `ssh` `scp` `git push` `rm -r` `sudo`). 복합 명령은 스크립트 파일로 감싼다. 첫 단어가 `./`·`/`로 시작하면 저장소 루트 기준으로 파일이 있고 실행 비트가 있어야 하고, 아니면 `command -v`로 풀려야 한다. ③ 사용자 확인: 문자열 검사는 스크립트 안의 동작을 못 보는 안전망이다. 그래서 init에서 조건·검증·Worker 호출 명령 목록을 보이고(`npm`·`yarn`·`pnpm`·`make`로 시작하면 package.json·Makefile에서 한 단계 풀어 실제 실행 줄도 함께) 사용자가 확인한 명령만 쓴다. ④ 실행 환경: 검사·실행 모두 인계 문서가 속한 저장소 루트(공유 트리)에서, 셸 없이 인자 배열로 직접, 환경 변수는 세션 것 그대로 쓴다. 종료 코드는 그 명령의 것이고 파이프가 없어 가려지는 실패도 없다. ⑤ 종료 코드: 126·127은 판정 명령 자체의 오류라서 나머지 `cmd:`를 돌리지 않고 즉시 `judge-fail`로 중단한다. 그 밖의 0이 아닌 코드는 조건 미달이다. 제한 시간을 넘긴 `cmd:`는 실패로 적고 프로세스를 끝낸다. `run`은 judge-fail이면 `stopped_reason`과 `중단:` 줄까지 쓰고 exit 3으로 끝난다. ⑥ 평가: `eval-goal.sh run <HANDOFF.md>`가 반복 수를 올리고 `cmd:`를 순서대로 한 번 돌려, exit 코드와 출력 꼬리 50줄을 `docs/relay/<plan>/goal/<반복번호>.log`에, 결과 한 줄을 `goal/eval.md`에 남기고 state.json `last_eval`을 갱신한다. 마지막 줄은 `DONE: complete` 또는 `DONE: incomplete(units=N,failed=M)`이다. 인계 문서 재개 블록에는 `최근 조건 평가: <반복번호> <시각> 통과 <수> 실패 <수> → goal/eval.md` 한 줄만 둔다(R12). ⑦ 재사용: `last_eval`에 저장소별 트리 키를 적는다(`eval-goal.sh treekey <HANDOFF.md> <slug>`로도 본다). 트리 키 = 임시 인덱스(`GIT_INDEX_FILE`)에 `git read-tree HEAD` → `git add -A -- . ':!docs/relay/<plan>'` → `git rm -r --cached -q --ignore-unmatch docs/relay/<plan>` → `git write-tree`한 트리 해시다. 계획 폴더가 무시 대상이면 제외 pathspec이 `git add`를 exit 1로 끝내므로(git 2.56 직접 확인) 그 제외를 빼고 올린다. 모든 대상 저장소의 트리 키와 `cmd:` 목록이 이전 평가와 같을 때만 재실행 없이 `(이전 실행 · 그 뒤 변경 없음)`으로 재사용한다. 미완료(`미착수`·`진행`·`보류`·`blocked`) 단위가 0개일 때의 평가는 재사용하지 않고 항상 새로 돌린다. ⑧ 완료 판정 = 미완료 단위 0개 AND 모든 `cmd:` exit 0. 상태표 전부 `완료`는 적지 않아도 항상 붙는 조건이고, 단위가 남았으면 `cmd:`가 통과해도 완료가 아니다. 모델이 스스로 채점하는 조건은 두지 않는다. ⑨ R2 적용: 조건은 빠른 것(대상 패키지 테스트·바뀐 파일 lint)으로 두고 전체 스위트는 2~3단위마다 1회다. 조건 명령은 반복마다 `eval-goal.sh`가 한 번만 돌리고, Worker 브리프에는 조건 명령 전체를 돌리지 말고 자기 변경의 대상 시험만 돌리라고 적는다 | 완료를 명령의 종료 코드로만 판정해야 사람이 없어도 끝을 정할 수 있다. 셸을 거치지 않아 파이프가 실패를 가리지 않고, 명령의 부작용은 init에서 사용자가 본 목록으로 한정된다 |
| R14 | **auto 경계·워크트리·복구.** 표기: `<wt>` = `docs/relay/<plan>/<unit>/wt/`, `<합집합>` = 계획 pathspec 합집합 경로. ① 시작 조건: `커밋 정책:`이 `자동 승인: <보정 단위 *-fix1·2 포함 단위 전부> / 만료: <계획 완료·중단·최대 반복 또는 최대 시간 도달>` 형식이 아니면 시작하지 않는다. 푸시는 자동 승인 대상이 아니다. 만료에 `YYYY-MM-DD HH:MM`을 쓰면 그 시각 뒤의 커밋을 `unit commit`이 `expired`로 막고, 정책 줄에 `소진`이 있어도 같다. 단위 하나 = 저장소 하나이고 pathspec 열은 `<slug>:<경로>`다. slug를 생략하면 인계 문서가 속한 저장소이고, 그 slug는 `저장소:` 줄에 같은 경로의 줄이 있으면 그 이름이며 없으면 저장소 루트 폴더 이름이다. 다른 저장소는 재개 블록의 선택 줄 `저장소: <slug>=<절대경로>`로 저장소마다 한 줄씩 정한다(slug는 영문·숫자·`.`·`_`·`-`, 경로는 절대 경로이며 형식이 틀리면 `check`가 거부한다). 어기면 `check`가 단위를 저장소별로 나누라고 거부하며, 검사·명령은 `<경로>`만 떼어 그 저장소에서 돌린다. `git status --porcelain -uall -- <합집합> ':!docs/relay/<plan>'`이 비어 있어야 한다(공유 트리의 합집합 파일 = HEAD). 아니면 시작하지 않고 사용자가 먼저 정리한다. pathspec 밖 변경은 두되 커밋하지 않는다. 저장소별로 `init_head`(현재 HEAD)·`expected_tip`(처음엔 `init_head`, 머지될 때마다 그 커밋)·`target_ref`(`git symbolic-ref HEAD`, 분리 HEAD면 거부)를 state.json에 적는다. 먼저 `eval-goal.sh check`를 돌려 R13 ③ 명령 목록과 함께 만들고 지울 자산(`<wt>` 워크트리·`relay/<plan>/<unit>` 브랜치)과 "무인 중 승인 창이 뜨면 멈춘다"를 보이고 한 번 확인받는다. 이 확인 1회가 유일한 질문 지점이며, 삭제 사전 확인과 closing 3항을 이 계획에 한해 미리 받는 것이다. 확인 뒤 `eval-goal.sh init`이 `check`를 다시 돌리고 위 검사와 state.json 기록을 한다(`모드: auto`가 아니거나 state.json이 이미 있으면 거부하며, 이어 하려면 resume). ② 경계(재개 블록 `경계:`): `최대 반복`(양의 정수, 기본 단위 수 × 2, 보정 단위 반복 포함)·`최대 시간`(state.json `started_at` 기준 벽시계, 기본 4h)·`Worker 제한`(Worker 호출 1회의 대기 상한, 기본 30m, herdr `--timeout`·agy `--print-timeout`). 시간 값은 `<정수>s`·`m`·`h` 형식이고 단위 없는 숫자는 거부하며, 줄을 생략하면 기본값을 쓴다. 최대 시간은 반복 앞·커밋 직전·반복 뒤에서 본다(경과 시간과 반복 수는 `eval-goal.sh status-json`으로 읽고, 커밋 직전은 `unit commit`이 직접 검사한다). `cmd:`는 R13 제한 시간으로, Worker는 `Worker 제한`으로 끊는다. 승인 창은 끊지 못한다: 뜨면 무인 실행은 거기서 멈춘 것이고 사람이 답하면 그 반복을 이어가며, 최대 시간은 그동안에도 흐르고 커밋 직전 재검사가 만료를 잡는다. 정체 경계는 없다(재위임이 unit 안에서 끝나 모든 반복은 단위를 `완료`하거나 중단한다). 권한은 지금 있는 것만 쓰고 권한 모드·허용 목록을 바꾸거나 요구하지 않는다. 사용자가 스스로 계획 기간 한정 허용을 넣기로 했다면 R1·closing 2항 절차(인계 문서 "종료 시 제거"에 적고 close에서 제거 확인)를 따르며, 스킬은 이를 권하지 않고 시작 조건으로 삼지 않는다. Worker가 agy면 셸을 못 쓰므로 시험은 이 세션이 워크트리에서 돌린다(pair 3절). ③ 단위 시작(공유 트리): `git rev-parse HEAD`가 `expected_tip`과 같고(다르면 남의 커밋이 들어온 것) 위 `status` 검사가 비어야 한다. 어긋나면 그 단위를 `blocked`로 적고 중단 점검으로 간다. 통과하면 행을 `진행`으로 바꾸고 `git worktree add -b relay/<plan>/<unit> <wt> HEAD`로 격리 워크트리 브랜치를 만들고 state.json `units[<unit>]`에 `repo`·`base_head`(= 이때의 HEAD)·`branch`·`wt`·`stage: started`·완료 기준 키를 적는다. 이 전부를 `eval-goal.sh unit <HANDOFF.md> <단위> start`가 한다(브랜치나 워크트리가 이미 있으면 거부하므로 recover나 discard를 쓴다). Agent 도구 `isolation: "worktree"`와 `commit-unit.sh`는 쓰지 않는다(워크트리는 자기 인덱스를 가져 R11 오염이 없다). R1의 "다른 저장소를 Worker가 직접 편집"은 "그 저장소의 워크트리에서 편집"이 된다. ④ Worker 띄우기(시작·재위임·복구에서 pane이 없을 때): herdr codex는 `herdr pane split --cwd <wt>` + `agent start <이 세션이 정한 이름>`, agy는 `cd <wt>`에서 `agy -p … --add-dir <wt>`(pair 스킬 2.1·3절). 탭의 사용자 pane은 쓰지 않는다. 위임·읽기·대기는 state에 적은 agent 이름으로 하고(pair 2.2 이름 탐지·2.3 고정 `codex` 타깃은 쓰지 않는다) pane id·agent 이름(agy는 PID·시작 시각)을 `eval-goal.sh state set units.<단위>.worker <JSON>`으로 `units[<unit>].worker`에 적는다. 브리프에는 `templates/BRIEF.md`의 auto 줄 4개를 넣는다. ⑤ 확인·검수(unit 3·4단계): `git -C <wt> reset -q HEAD`로 인덱스를 비우고(Worker의 `git add` 무효화) `git -C <wt> status --porcelain -uall`에서 `.relay-logs/`를 뺀 전부를 본다. pathspec 밖 파일이나 권위 관문 파일(R15)이 있으면 즉시 `blocked`(파일 목록은 이월). 없으면 `git -C <wt> add -A -- <경로> ':!.relay-logs'` 뒤 `git -C <wt> diff --cached HEAD`로 본다(신규 파일·바이너리 포함). reset부터 `add -A`까지와 범위 밖 `blocked` 기록은 `eval-goal.sh unit … checkwt`가 하고 `diff --cached --stat`을 보여 준다. 전체 diff는 세션이 읽는다. 독립 검수는 같은 cached diff + 신규 시험이고, 통과하면 세션이 `eval-goal.sh state set units.<단위>.stage reviewed`로 `stage: reviewed`를 적는다. 결함·지적은 같은 워크트리에서 Worker 재위임으로 고친다: 재위임 전 `reset -q HEAD`로 인덱스만 비우고(작업 파일은 그대로) 수정 뒤 상태 검사·`add -A`·cached diff를 다시 만들어 델타 재검수한다. ⑥ 재위임 키: 완료 기준당 2회(기존)다. state.json `redelegations`에 완료 기준 키별로 적고 반복·세션 교체로 초기화하지 않는다. 일반 단위의 키는 단위 이름이고, 보정 단위의 키는 `fix add --key`로 준 값이다(실패한 `cmd:` 줄, 통합 검수 지적이면 `integration`). 같은 키의 보정 단위들은 한 카운터를 나눠 쓴다. 재위임 직전마다 `eval-goal.sh redeleg <키> incr`를 부른다. 3번째는 거부(exit 1)하므로 세션이 `eval-goal.sh stop blocked:<단위>`로 그 단위 행을 `blocked`로 적는다. ⑦ 커밋(`<wt>` 안, unit 5단계. (a)~(c)는 `eval-goal.sh unit … commit -m <메시지>`가 하고 (d)는 `unit … merge`가 머지 직전에 한다): (a) 재검사 — 중단 상태(`stopped_reason`이 비어 있지 않음)가 아님·최대 시간·자동 승인 만료·권위 관문, `reset -q HEAD` 뒤 `git -C <wt> status --porcelain -uall`에서 `.relay-logs/`를 뺀 전부가 pathspec 안. (b) `git -C <wt> add -A -- <경로> ':!.relay-logs'`. (c) staged diff가 비면 커밋하지 않는다(`NOCHANGE`를 찍는다. 검증된 무변경 단위이고 기록은 (d) 뒤). 아니면 `git -C <wt> commit`(단위 메시지) 후 `stage: committed`와 `commit`을 기록한다. (d) 공유 트리 확인(무변경도 같다): `git symbolic-ref HEAD` == `target_ref`(분리 HEAD·다른 브랜치면 `blocked`), `git rev-parse HEAD` == `base_head`(= `expected_tip`. 다르면 `blocked`이고 남의 커밋이 pathspec 밖이어도 같다. 무인 중 공유 브랜치는 이 세션만 움직인다는 전제다), `<합집합>` 상태 검사가 빔. 커밋이 있으면 `git diff --name-only --diff-filter=A <base_head> relay/<plan>/<unit>`으로 들어올 새 파일 목록을 구해, 비어 있지 않을 때만 `git ls-files -o -i --exclude-standard -- <그 파일들>`이 비어 있는지 본다(겹치는 무시 파일이 있으면 `blocked`). 무변경이면 `unit … merge`가 (d) 통과 뒤 `commit: 없음(변경 없음)`과 행 `완료`를 적고, REPORT에 사유는 세션이 적는다. ⑧ 머지(`eval-goal.sh unit … merge`): `git merge --ff-only --no-autostash --no-overwrite-ignore relay/<plan>/<unit>`. 거부되면 공유 트리는 그대로 두고 `blocked`다(워크트리 브랜치 커밋은 남는다). 검사~머지 틈은 `--ff-only`와 git의 덮어쓰기 거부가 막는다(머지가 바꾸지 않는 파일을 그 틈에 남이 고친 것은 미커밋으로 남고, `<합집합>` 안이면 다음 단위 시작 검사가 잡는다). 머지 직후 재검증한다: `git symbolic-ref HEAD` == `target_ref`이고 `git rev-parse <target_ref>` == `<commit>`이어야 한다. 아니면 어떤 ref도 되돌리지 않는다(체크아웃 경쟁 때문. 작업 트리·인덱스도 그대로): 전진한 ref·분리 HEAD를 `units[<unit>].ff_misapplied`에 적고 `blocked`(사람이 `git reset`·`git switch`로 정리한 뒤 그 키를 지운다. 이 기록이 있으면 merge·recover를 거부한다). ff 직전에는 ff 전 ref 스냅샷을 뜨고 잠금 안에서 `stage: merging`·`merge_intent`(스냅샷 포함)를 먼저 적는다(ff 뒤 기록에 실패해도 recover가 같은 스냅샷으로 미확정 머지를 알아본다. `merging`인 단위는 merge·cleanup을 거부하고 recover만 받는다). git을 돌리는 하위 명령은 `goal/.driver`를 명령 내내 쥔다(한 계획에 하나만. 두 번째는 기다리지 않고 거부. git 자식이 물려받아 스크립트가 죽어도 git이 끝날 때까지 산다). 통과하면 `expected_tip`을 `<commit>`으로(무변경이면 그대로) 갱신하고 상태표 행을 `완료`(커밋·종료 시각)로 적고 `stage: merged`로 한다. ⑨ 정리: 세션이 그 단위의 Worker pane(이 세션이 띄운 것만)을 먼저 닫는다. 이어 `eval-goal.sh unit … cleanup`이 `<wt>/.relay-logs/`가 있으면 단위 폴더로 옮기고(`REPORT.md`는 `docs/relay/<plan>/<unit>/`에, 나머지는 `logs/`에. 이름이 겹치면 번호를 붙이고 빈 폴더는 `rmdir`) → `git worktree remove <wt>` → 성공하면 `git branch -d relay/<plan>/<unit>`를 한다. 둘 다 성공해야 `stage: cleaned`다. 제거가 실패하면(미추적 비무시 파일이 남은 경우 등. 이런 파일은 ⑦ (a)에서 먼저 걸리고, 무시 파일은 제거를 막지 않는다) `branch -d`도 하지 않고 `merged`로 두고 이월에 적는다. 강제 삭제(`worktree remove --force`·`branch -D`)는 하지 않는다. 인계 갱신(unit 6단계)은 공유 트리 `docs/relay/<plan>/`에 이 세션이 쓰며, 이 문서는 커밋 대상이 아니다(커밋 여부는 close에서 사용자가 정한다). ⑩ 복구 분기(`eval-goal.sh unit … recover`가 판정하고 한 단어로 답한다. 매 반복 시작과 재개 때, 새 단위보다 먼저, `stage ≠ cleaned`인 단위마다. `stage`는 참고값이고 git 실제 상태가 기준): 브랜치가 있고 tip ≠ `base_head`인데 `commit`이 비어 있으면 `commit = tip`을 채운다. 그 뒤 — `commit`이 해시이고 공유 HEAD의 조상이거나 `commit: 없음(변경 없음)`이면 머지된 단위다: 남은 pane·로그·워크트리·브랜치를 ⑨대로 정리하고 행이 미완료면 `완료`·커밋·종료 시각을 적고 `expected_tip`을 맞춘다. 브랜치가 있고 tip ≠ `base_head`이고 조상이 아니면 공유 트리 확인과 머지(⑦ (d)·⑧)부터. 브랜치가 있고 tip == `base_head`이면 `stage: reviewed`일 때 커밋(⑦)부터, 아니면 Worker부터(pane이 없으면 새로 띄운다). 브랜치도 `commit`도 없고 행이 미완료면 단위 시작(③)부터. 출력 단어는 `start`(③부터)·`worker`·`review`(커밋부터)·`merge`(머지부터)·`cleanup`(⑨부터)·`done`이다. 사용자가 `blocked` 행을 `미착수`로 되돌린 단위는 다시 쓰지 않는다(`eval-goal.sh unit … discard`가 Worker pane 이후를 처리하고 `units[<unit>]`·재위임 키도 지운다): Worker pane 닫기(세션, 전이표 4행) → `.relay-logs/`를 `logs/`로 옮기기(버린 시도의 `REPORT.md`도 `logs/`로 간다) → 워크트리 제거(실패하면 사용자가 정리할 때까지 멈춘다) → 브랜치는 미머지 커밋이 있어 `branch -d`가 안 되므로 지우지 않고 `relay/<plan>/<unit>.discarded-<n>`으로 이름을 바꿔 보존(지울지는 close에서 사용자가 정한다). 그 뒤 현재 HEAD 기준으로 처음부터 한다. ⑪ 보정 단위: 단위가 전부 `완료`인데 `cmd:`가 실패하면 계획자가 원인을 확인한다. 수정 대상 파일이 모두 `<합집합>` 안일 때만 상태표 끝에 보정 단위를 더한다(두 저장소에 걸치면 저장소별로 나눈다). 더하기는 `eval-goal.sh fix add <이름> --key <키> --repo <slug> --files <경로,...> --summary <한 줄>`이 하며, 3회차는 `fix-cap`으로, 계획 pathspec 밖 파일은 `scope`로 중단까지 기록하고 거부한다. 이름은 `U<마지막 원래 단위>-fix<회차>-<저장소 slug>`(저장소 하나면 slug 생략)이고, `fix_units`에 회차·단위명·완료 기준 키를 적은 뒤 경계 점검(뒤)·교체 판단을 거쳐 다음 반복으로 간다. 계획당 2회차까지(한 회차에 저장소별 단위 여러 개 가능)이고 그 뒤 또 실패하면 단위를 더하지 않고 `fix-cap`으로 중단한다. 파일을 특정하지 못하거나 `<합집합>` 밖이거나 새 기능·목표가 필요하면 범위 확장이므로 `scope`로 중단한다. 상태표 열 기본값: 단위 = 위 이름, 내용 = 실패 요약 한 줄, 파일·pathspec = 수정 대상 파일, 선행 = 직전 행 단위, 모델·검수 = 직전 단위와 같게, 병렬 = `✘`, 가중치 = 빈칸, 상태 = `미착수`, 종료 시각·커밋 = 빈칸. ⑫ Worker 중단: Worker pane이 죽거나 `Worker 제한`을 넘기면 실패 1회로 센다. 제한을 넘긴 Worker는 먼저 멈춘다: herdr는 그 pane에 `esc`를 보내고 최대 2분 안에 `idle`이 되는지 본다. `idle`이면 같은 워크트리에서 재위임하고, 아니면 그 단위를 `blocked`로 적고 중단한다(쓰기 주체 둘 금지). agy는 `--print-timeout`이 프로세스를 끝낸다. 전이표 `""` 행의 재개도 같은 절차를 쓴다(세션이 죽어도 Worker pane은 살아 있을 수 있다). 재위임 브리프에는 "워크트리에 이전 시도의 수정이 남아 있다. `git status`·`git diff HEAD`로 먼저 본다"를 적는다(agy는 이 세션이 그 목록을 브리프에 적어 ## 진행률·남은 시간 산정

- 진행률 = 기준선 + Σ(완료 단위 가중치). 가중치 열이 비면 (100 − 기준선) / 단위 수 로 균등. ±10%p 로 보고, 파일·테스트 개수로 환산하지 않는다.
- 남은 시간 = 최근 완료 단위들의 `종료 시각` 간격 중 4시간 초과(밤샘·대기)를 제외한 값의 중앙값 × 남은 단위 수, 범위는 1·3사분위 × 남은 단위 수. 커밋이 없는 단위도 종료 시각은 적는다.

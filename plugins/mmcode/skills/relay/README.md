# relay 사용법

큰 작업을 단위로 쪼개 한 단위씩 끝내는 스킬이다. 진행 상황을 인계 문서에 적어 두므로 세션이 바뀌어도 이어 간다. 자리를 비워도 끝까지 혼자 하는 `auto` 모드가 있다.

절차 상세는 `SKILL.md`, 규칙은 `references/rules.md`에 있다. 이 문서는 "무엇을 말하면 되는가"만 적는다.

## 기본 사용 (사람이 지켜보는 경우)

1. 프로젝트 폴더에서 Claude에게 말한다. `/mmcode:relay 이 작업을 단위 계획으로 만들어줘. <작업 설명>`
2. Claude가 단위 표와 인계 문서를 `docs/relay/<계획 이름>/`에 만든다. 사용자는 표를 보고 수정할 곳만 말한다.
3. "다음 단위 진행해"라고 말한다. Claude가 단위 하나를 작업하고 검수한 뒤 "커밋할까요?"라고 묻는다.
4. 대화가 길어지면 "세션 바꿔서 이어 가"라고 말한다. herdr 탭 안이면 새 세션이 자동으로 뜬다. 밖이면 Claude가 인계 문서를 갱신하고 새 세션 시작 방법을 안내한다.
5. 새 세션에서는 "인계 재개 `docs/relay/<계획 이름>/HANDOFF.md`"라고 말한다. 상태표가 뜨고 그다음 단위부터 이어 간다.
6. 단위가 다 끝나면 "close 해줘"라고 말한다. Claude가 임시 권한·브랜치를 정리하고 종료 체크리스트를 보여 준다.

## auto 모드 (자리를 비우는 경우)

완료 조건 명령이 통과할 때까지 Claude가 혼자 단위를 반복한다. 사용자는 시작할 때 한 번만 확인한다.

**쓸 수 있는 조건**

- 완료를 명령으로 판정할 수 있다. 예: `npm test`가 exit 0.
- 단위가 2개 이상이다.
- 이 계획에 한해 커밋 자동 승인을 준다. 푸시는 자동 승인에 들어가지 않는다.

**시작하는 법**

Claude에게 한 문장을 말한다. 인계 문서는 Claude가 만든다. 사용자가 직접 쓰지 않는다.

```text
/mmcode:relay 이 작업을 단위 계획으로 만들고 auto로 돌려줘.
완료 조건은 `npm test`. 최대 8번, 4시간까지. 이 계획 안의 커밋은 자동 승인.
```

작업 설명·테스트 명령·횟수·시간만 본인 것으로 바꾼다. 그 뒤는 이렇다.

1. Claude가 인계 문서를 만들고 "이 명령으로 끝을 판정하고 이 브랜치들을 만든다. 맞나?"라고 한 번 묻는다. "네"라고 답한다. 이것이 유일한 질문이다.
2. 자리를 비운다.
3. 돌아와서 결과를 본다.
   - `완료`로 끝났으면 "close 해줘"라고 말한다. Claude가 단위별 커밋을 하나씩 보여 주고 사용자가 확인한다.
   - `중단`으로 끝났으면 Claude가 막힌 이유를 보여 준다. 사용자가 고칠지 결정한다. 고친 뒤 "인계 재개"라고 말하면 다시 돈다.

**혼자 돌 때 하는 일**

- 단위 하나를 따로 만든 브랜치에서 끝내고 본 브랜치에 합친다. 그사이 사람이 본 브랜치를 바꿨으면 합치지 않고 멈춘다.
- 합친 뒤 완료 조건 명령을 돌린다. 통과하면 끝이다. 실패하면 고치는 단위를 하나 더 만들어 다시 한다. 고치기는 계획당 2번까지다.
- 정한 횟수나 시간을 넘으면 멈추고 이유를 인계 문서에 적는다.
- 어디까지 했는지를 매번 `goal/state.json`에 적어 둔다. 세션이 죽어도 다음 세션이 그 파일을 읽고 이어서 한다.
- 대화가 차면 herdr 탭 안에서 새 세션을 띄워 넘긴다. herdr 밖이면 멈추고 새 세션 시작을 안내한다.

**하지 않는 일**

커밋만 자동이다. 푸시, PR 만들기, 원격 머지, 브랜치·워크트리 강제 삭제, 권한 변경은 하지 않는다. 승인 창이 뜨면 거기서 멈춘다.

## 부르는 말

- auto를 쓸 때는 항상 **"relay auto"** 또는 "relay를 auto로"라고 말한다. "auto 모드"라고만 말하면 Claude Code 권한 설정의 auto mode와 헷갈릴 수 있다.
- Codex에서는 `/mmcode:relay` 대신 `$mmcode:relay`를 쓴다.
- 반복에 쓰는 `/loop`는 Claude가 알아서 켜고 끈다. 사용자가 부를 일은 없다.

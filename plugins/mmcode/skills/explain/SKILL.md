# explain — 먼저 설명

작업 전에 요청을 어떻게 이해했는지와 무엇을 어떻게 고칠지를 먼저 보여준다. 이 설명은 승인 요청이 아니다. 설명한 뒤 바로 작업을 이어간다. 단, 아래의 '계획만'·'승인 후 진행' 같은 지시가 있으면 화면을 보여준 뒤 멈춘다.

이 스킬은 이해와 범위 설명만 맡는다. 계획 수립·위임·검증·진행 알림·완료 보고는 `plan`이 맡는다. plan을 함께 쓰지 않으면 이 화면을 보여준 뒤 평소대로 작업하고 보고한다. Claude와 Codex에서 같은 방식으로 쓴다.

## 먼저 판단할 것

- 프로젝트의 AGENTS.md·CLAUDE.md와 관련 코드·재사용 자산을 필요한 만큼 읽는다. 프로젝트별 명령·주소·브라우저 규칙을 이 스킬에 옮겨 적지 않는다.
- 사용자의 목표, 기존 권한과 금지 사항을 우선한다. 이 스킬은 커밋·푸시·배포·DB 변경을 허가하지 않는다.
- 사용자가 '계획만', '아직 수정하지 마', '승인 후 진행'이라고 하면 읽기와 분석까지만 한다.
- 모르는 정보가 결과나 범위를 실제로 바꿀 때만 질문한다. 질문하면 닫는 굵은 선 아래, 코드 블록 안에 `질문:` 줄을 쓰고 답을 기다린다. 흔히 쓰는 기본값이 하나로 분명하거나 결과를 바꾸지 않는 불확실성은 `가정:`으로 쓰고 바로 진행한다. 기본값 후보가 여럿이면 질문한다. 이미 답한 내용과 권한은 다시 묻지 않는다.

## 작업 이해 화면 (반드시)

작업 규모와 관계없이 작업 전에 이 화면을 먼저 보여준다. 블록 제목 `📋 이해한 내용`과 `🎯 작업 방법`은 이 순서 그대로 쓴다. plan에서 일꾼을 쓰면 작업 계획 화면이 이 화면을 대신한다.

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 작업 이해 │ 목록 날짜 필터 버그
 난이도 ★★☆☆☆ · 수정 파일 1개
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 📋 이해한 내용
    ▸ 날짜를 바꿔도 목록이 그대로임
    ▸ 날짜에 맞는 목록이 나오게 고침
    ▸ 가정: 검색 버튼 자체는 정상

 🎯 작업 방법
    ▸ 조회 요청에 빠진 날짜 값을 넣음
    ▸ 날짜 3가지로 목록·전체 건수를 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 쓰는 법

- 쉬운 말로 짧게 쓴다. 한 줄에 한 가지만 쓴다. 내부 설계 용어는 풀어 쓴다.
- **📋 이해한 내용**: 목표, 바뀌는 동작·화면·데이터, 헷갈리기 쉬운 제외 범위를 쓴다. 확실하지 않은 내용은 `가정:`으로 시작한다.
- **🎯 작업 방법**: 고칠 위치와 방식, 확인 방법을 쓴다.
- **작은 수정**(간격·문구·스타일, 원인이 분명한 버그): 블록마다 꼭 필요한 줄만 쓴다. 보통 2~3줄이다. `가정:` 줄과 plan이 더하는 줄은 이 수에 넣지 않는다.
- **큰 작업**(여러 서비스·DB·주요 동작 변경): 필요한 줄만 더한다. 제약, 배포 순서, 데이터 보정이 있으면 🎯 작업 방법에 넣는다. 줄 수를 채우려고 항목을 만들지 않는다.
- 사용자가 자세히 물으면 그때 늘린다.

### 화면 규칙

- `text` 코드 블록 안에 쓴다. 그래야 터미널에서 줄이 맞는다.
- 머리 부분은 두 줄이다. 첫 줄은 `작업 이해 │ <작업 이름>`, 둘째 줄은 `난이도 ★★☆☆☆ · 수정 파일 N개`다.
- 작업 이름은 공백을 포함해 한글 12자 안으로 줄인다. 수정 파일 수에는 시험 파일도 센다. 모르면 `수정 파일 확인 중`으로 쓴다.
- 난이도는 별 5개 중 칠한 개수다.
  - ★1: 문구·스타일 수정
  - ★2: 원인이 분명한 버그, 또는 작은 함수·옵션 추가
  - ★3: 원인을 찾아야 하는 버그, 또는 화면 하나의 기능 추가
  - ★4: 여러 파일·모듈에 걸친 변경
  - ★5: 여러 서비스·DB·배포 순서가 얽힌 변경
- 굵은 선(`━`) 50칸으로 머리 부분의 위아래와 화면 끝을 닫는다. 오른쪽 세로선은 긋지 않는다. 한글과 이모지 폭이 터미널마다 달라 어긋나기 때문이다.
- 이모지는 블록 제목 두 곳(📋·🎯)에만 쓴다.
- 항목은 4칸 들여 `▸`로 시작한다. 한 항목은 공백 포함 한글 20자 안팎으로 쓴다. 길면 두 항목으로 나눈다. 줄이 굵은 선보다 조금 길어져도 화면은 깨지지 않는다. 글자 수를 맞추느라 뜻을 줄이지 않는다.
- 이 틀 밖의 장식은 더하지 않는다. 멈춤·커밋 확인 같은 안내는 화면 아래에 일반 문장 1~2줄로 쓴다.

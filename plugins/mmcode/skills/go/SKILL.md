# go — 작업 입구

작업 종류를 고르고 맞는 절차를 연다. 절차는 기존 스킬을 가리키거나 `playbooks/` 안의 짧은 파일이다. Claude와 Codex에서 같은 방식으로 쓴다.

## 0. 전제

- 전역 규칙(CLAUDE.md·AGENTS.md)이 항상 우선한다. 이 스킬은 자율성·승인 경계·커밋·모델 등급·답변 문체를 다시 정하지 않는다.
- 세션에 자동으로 켜지는 모드(ponytail·caveman 등)는 그대로 적용된다.
- 기존 스킬은 그대로다. `/explain`·`/mmcode:plan`·`/relay`를 직접 불러도 된다(`/plan`은 Claude Code 내장 명령과 겹치므로 접두사를 붙인다). 이 스킬은 그 위에 얹힌다.
- 하위 에이전트 도구가 없으면 모든 단계를 직접 한다. 절차 파일이 달리 정하면(예: 스킬 평가는 알리고 멈춤) 그쪽을 따른다.

## 1. 흐름

1. 요청을 읽고 2절 표에서 **경로 하나**를 고른다. 고르는 규칙은 3절. 고르면 바로 `▶ 경로: <경로 이름>` 한 줄을 쓴다. 긴 작업으로 감싸면 `▶ 경로: 긴 작업 › 리팩터`처럼 쓴다.
2. 화면을 띄우는 경로는 버그 수정·기능·리팩터·화면 일치·성능 문제·지표 개선 반복·검증 스크립트·긴 작업이다. explain 화면을 한 번 띄운다. 절차 파일이 화면 띄우는 단계를 따로 두면(예: 버그 수정은 재현 뒤) 그 자리에서, 없으면 첫 단계 전에 띄운다. 🎯 작업 방법 블록 끝에 `▸ 경로: <경로 이름>` 줄을 더한다. plan이 `▸ 방침:` 줄을 더하면 그 앞에 둔다. 나머지 경로(조사·실행 중 진단·프로파일 분석·변경 영향 범위·시제품·재개·페어·코드 리뷰·교차 검증·스킬 평가)는 화면 없이 1단계의 `▶` 줄만 쓴다.
3. 절차 파일이 있으면 그 단계를, 없으면 가리키는 스킬의 절 번호(예: 긴 작업은 relay `init` → `unit` 반복 → `close`)를 번호 목록으로 답변에 적는다. 안 하는 단계는 지우지 않고 `건너뜀: <이유>`로 남긴다.
4. 단계가 기존 스킬을 가리키면 그 스킬을 따른다. 진행 알림은 plan 8절 형식을 쓴다.
5. 끝은 절차가 정한 보고 형식으로 한다(5절).

## 3. 경로 고르는 규칙

- 둘 이상 맞으면 더 좁은 쪽을 고른다. 예: 느리다는 보고에 지표 목표가 있으면 `지표 개선 반복`, 목표 없이 한 번 고치면 `성능 문제`.
- 맞는 게 없으면 코드 변경은 `기능`, 그 외는 `조사`.
- trace·프로파일이 걸린 요청: 파일이 이미 있으면 `프로파일 분석`, 직접 떠야 하면 `실행 중 진단`, 고치는 것까지 요청이면 `성능 문제`.
- 세션 하나에 끝나지 않을 것 같으면(여러 모듈·파일 10개 넘는 변경, 또는 사용자가 "세션 나눠서"라고 하면) 원래 경로를 `긴 작업`으로 감싼다. 감싸기는 경로 두 개가 아니다. 단위마다 안쪽 경로의 절차를 따르고, 안쪽 경로의 화면도 단위마다 띄운다.
- `실행 중 진단`·`프로파일 분석`은 고치지 않는다. 고치려면 진단을 끝낸 뒤 `버그 수정`이나 `성능 문제`로 새로 시작한다.
- 코드 리뷰·교차 검증은 다른 경로의 마지막 단계로도 들어간다. 발동 조건은 plan 5절과 전역 규칙을 따른다.
- 경로 선택이 틀렸다고 중간에 알면 `📐 범위 변경 │ 경로 기능 → 리팩터 · <이유>` 한 줄로 알리고 바꾼다.

## 4. 원칙

`references/principles.md`에 판단 기준이 있다. 결정이 갈릴 때 읽는다. 결정을 실제로 바꾼 원칙만 완료 보고 아래에 일반 문장 한 줄로 적는다. 예: `원칙: 전제 의심 · 캐시 대신 쿼리를 확인함`. 바꾼 결정이 없으면 쓰지 않는다. 원칙 이름을 늘어놓지 않는다.

## 5. 보고

- 코드를 바꾼 경로: plan 9절 작업 완료 화면. 라벨을 새로 만들지 않는다. 원칙 줄은 화면 아래 일반 문장으로 쓴다.
- 긴 작업: 단위마다 relay 형식(REPORT.md·인계 문서 갱신)으로 보고한다. 계획 전체가 끝나면 plan 완료 화면을 한 번 쓴다.
- 코드를 바꾸지 않은 경로(조사·진단·분석·평가): 절차 파일이 정한 형식. 공통 뼈대는 결론 1~2줄 → 근거(file:line 또는 측정값) → 확신도(`investigation.md` 4단계의 확신도 표) → 다음 할 일 하나.
- 숫자는 실행한 결과만 쓴다. 하지 않은 검사는 `미실행 · <이유>`. 확인하지 못한 것은 `미확인`.

## 6. 금지

- 전역 규칙을 완화하거나 다시 쓰는 것. 커밋·푸시·삭제·외부 전송의 자동 실행.
- `긴 작업` 감싸기 외에 경로 두 개를 동시에 여는 것. 단계를 표기 없이 빼는 것.
- 절차 파일에 없는 단계를 경로 이름으로 꾸미는 것.
- 소스나 대화를 하위 에이전트에 통째로 붙이는 것. 경로·절·완료 기준만 준다.

# 실행 중 진단
언제: 누수·CPU 공회전·간헐 오류를 살아 있는 프로세스에서 찾을 때. 진단만 한다. 고치지 않는다.
## 단계
1. 소스만 읽고 추론하지 않는다. 살아 있는 프로세스를 계측한다. 저장소의 소스는 바꾸지 않는다.
2. 살아 있는 신호를 파일로 잡는다. 추측은 신호가 아니다.
   - CPU 공회전: CPU 프로파일
   - 누수: heap snapshot
   - 화면 이상: CDP trace. 웹 화면은 프로젝트·전역 규칙이 정한 브라우저 도구로 접근한다.
3. 파일을 결정적 증거로 줄인다. 시간을 가장 많이 쓰는 호출 흐름, 누수 객체를 GC root까지 붙잡는 참조 사슬(retainer chain), 입력 없이 도는 반복을 찾는다.
   - 큰 파일은 하위 에이전트가 파싱한다. 줄인 결과만 가져온다.
4. 믿기 전에 원리를 증명한다. 실행 중인 프로세스에 CDP eval로 계측을 넣거나, 다시 불러오지 않고 라이브 코드를 임시로 바꿔 가설을 싸게 확인한다.
   - 로컬·개발 프로세스에만 한다. 운영 프로세스는 사용자에게 먼저 확인한다.
5. 결과를 소스에 연결한다. 파일, 심볼, 할당하거나 예약하는 줄까지 적는다.
## 보고
`investigation.md` 보고 형식을 쓴다. 결론 → 근거(file:line) → 확신도 → 다음 할 일 하나.
근거에 잡은 신호, 원리를 증명한 방법, 파일 위치를 넣는다. 원인을 알았으면 다음 할 일에 `버그 수정`이나 `성능 문제` 경로를 적는다.

# 스킬 평가
언제: 스킬·프롬프트 변경이 에이전트 행동을 바꾸는지 블라인드로 비교할 때.
## 단계
1. 하위 에이전트 도구가 있는지 먼저 본다. 없으면 그 사실을 알리고 멈춘다. 직접 후보 역할을 대신하면 블라인드가 깨진다.
2. 블라인드 규칙을 지킨다. 하나라도 어기면 비교가 무효다.
   - 후보가 보는 폴더·파일·프롬프트에 `eval`, `test`, `judge`, `experiment`, `rubric`, `score`, `compare`, `benchmark`, `candidate`, `arena`를 쓰지 않는다. 한국어 대응어(평가·시험·판정·채점·기준표·후보·비교)도 쓰지 않는다.
   - 후보 프롬프트는 실제 사용자 요청처럼 쓴다. 목표만 말하고 측정 의도는 말하지 않는다.
   - 후보에게 어떤 스킬·원칙·파일을 적용했는지 나열하라고 시키지 않는다. 설계 메모는 일반적으로만 요청한다.
   - 폴더와 슬러그 이름은 사용자가 고를 법한 프로젝트 이름으로 짓는다. 다른 후보가 있다고 알리지 않는다.
   - 판정자는 판정하는 줄 알아도 된다. 산출물은 가린 이름표로만 보여 주고 모델 이름은 알려 주지 않는다.
   - 두 변형을 비교하면 판정자 하나가 두 묶음을 한 번에 한 척도로 채점한다. 어느 묶음인지 모르게 한다.
3. 틀을 잡는다. 시험할 변형과 성공으로 볼 행동을 적는다. 기준표(구체 기준 3~6개)는 판정자만 본다.
4. 후보마다 정리한 작업 폴더를 scratch 폴더 안에 만든다. 변형을 넣고, 실제 요청이라면 있을 맥락(프로젝트 뼈대, 자연스럽게 읽을 스킬)을 깔아 둔다.
5. 프롬프트를 하나 쓴다. 사용자가 실제로 칠 법한 요청이다.
6. 후보 N개를 병렬 하위 에이전트로 띄운다. 같은 프롬프트를 주고 각자 자기 폴더에서 일하게 한다. 모델은 서로 다르게 고르고 등급은 plan 3절 등급 표를 따른다.
7. 판정자 1개를 띄운다. 후보와 다른 모델로 하고, 가능하면 다른 계열로 한다. 기준표와 가린 산출물만 준다.
8. 변형을 따랐는지는 후보의 자기 보고가 아니라 실제로 연 파일로 판단한다. 후보의 실행 기록에서 연 파일을 확인하고 코드 모양과 함께 본다.
   - 현재 작업 폴더의 기록만 읽는다. 다른 프로젝트의 대화 기록은 읽지 않는다.
   - 기록을 못 보면 `미확인`으로 쓴다.
9. 후보 산출물을 처음부터 끝까지 직접 읽는다. 판정자의 결론과 비교한다. 어긋나면 판정자가 치우쳤거나 기준표가 모호한 것이다. 그 뒤 종합한다.
## 보고
시험한 변형, 기준표, 후보별 메모, 판정자의 결론, 직접 낸 종합을 쓴다.
변형을 채택할지 추천을 붙인다.

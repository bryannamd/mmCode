# 버그 수정
언제: 보고된 결함을 고칠 때. 재현 → 원인 → 실패 시험 → 수정 순서다.
## 단계
1. 먼저 직접 재현한다. 재현하기 전에는 원인을 추측하지 않는다.
   - 재현이 안 되면 조건을 좁히거나 로그를 넣어 다시 시도한다.
   - 사용자에게 재현을 부탁하는 것은 도구로 닿지 않는 이유를 구체적으로 댈 수 있을 때만 한다.
2. 원인을 못 찾으면 이분 탐색한다. `git bisect`나 코드 범위 반분으로 범위를 절반씩 줄인다.
   - 단계마다 실행 결과로 한쪽을 지운다.
   - 남은 원인이 어떻게 일어나는지 실행 증거로 확인한 뒤에 고친다.
3. explain 화면을 띄운다. 작업 방법 블록 끝에 `▸ 경로: 버그 수정` 줄을 더한다. plan의 `▸ 방침:` 줄이 있으면 그 앞에 둔다.
4. plan 절차를 따른다.
   - 4절 "실패 먼저 확인"에 따라 고치기 전에 시험이 실패하는지 본다.
   - 시험으로 잡기 어려우면 1단계의 재현 절차가 실패 증거다.
   - 증거가 뒷받침하는 가장 작은 수정만 넣는다. "혹시 도움될" 방어 코드는 넣지 않는다.
   - 고친 뒤 같은 방법으로 다시 재현해 통과를 확인한다.

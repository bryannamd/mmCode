# 리팩터
언제: 동작은 그대로 두고 구조만 바꿀 때. 새 동작이나 버그 수정은 섞지 않는다.
## 단계
1. 동작 고정 시험부터 만든다. 현재 동작을 그대로 잡는 시험, 스냅샷, 옛·새 출력 비교 스크립트 중 하나를 쓴다.
   - 타입 검사와 lint는 동작 고정이 아니다.
   - 시험이 없는 영역은 구조를 건드리기 전에 시험부터 쓴다.
2. 작은 단계로 옮긴다. 단계마다 고정 시험이 통과해야 다음 단계로 간다.
   - 조건 분기나 잘못된 상태를 없애는 변경만 한다. 간접 층만 늘리는 변경은 하지 않는다.
3. API를 바꾸면 호출처를 전부 새 API로 옮긴다.
   - 이름 변경은 문자열·문서·주석에 남은 옛 이름까지 실제 파일에서 확인한다.
   - 호환용 shim을 두지 않는다. 한 단위 안에서 옮긴 호출처는 옛 API를 남기지 않는다. 여러 단위로 나누면 단위 경계에서만 둘이 공존하고, 마지막 단위에서 옛 API를 지운다.
4. 옛 API 삭제는 사용자에게 먼저 확인한다(전역 규칙: 삭제는 사전 확인). 확인 전에는 지우지 않는다.
5. plan 절차를 따른다.
   - 컴파일되는 것은 증거가 아니다. 실제 산출물로 동작이 그대로인지 확인한다.
   - 큰 변경은 옛 출력과 새 출력을 비교하는 스크립트를 돌린다.

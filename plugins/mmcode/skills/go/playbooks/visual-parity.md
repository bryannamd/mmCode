# 화면 일치
언제: 두 구현의 화면을 픽셀까지 맞출 때, 또는 스타일 체계를 옮길 때. 기준 이미지가 명세다.
## 단계
1. 기준 이미지부터 만든다. 옮기기 전에 현재 컴포넌트를 상태별로 찍는 스크린샷 비교 도구를 만든다.
   - 두 구현을 맞추는 경우 목표 쪽도 찍는다.
   - 기준 이미지가 없으면 일치를 주장하지 않는다. 후속 작업이 아니라 선행 조건이다.
2. 지름길을 쓰지 않는다. 비교 도구를 고치지 않는다. 기준 이미지를 건드리지 않는다. diff를 통과시키려고 컴포넌트 구조를 바꾸지 않는다.
   - 기준 이미지가 틀려 보이면 멈추고 사용자에게 묻는다. 직접 고치지 않는다.
3. 컴포넌트를 하나씩 옮긴다. 공유 부품을 먼저 옮긴다. 병렬로 하려면 컴포넌트마다 담당 하나와 별도 작업 폴더를 둔다.
4. 컴포넌트마다 기준 이미지와 픽셀 diff로 확인한다. 스크린샷과 diff는 프로젝트·전역 규칙이 정한 브라우저 도구로 한다.
5. diff가 0이 아니면 실패다. 픽셀 차이의 원인을 찾아 고친다. 컴포넌트마다 diff가 0이 될 때까지 반복한다.
6. 컴포넌트마다 또는 안전한 묶음마다 끝에 커밋할지 묻는다. 자동 커밋은 금지다.

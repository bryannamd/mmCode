# Notes 검증 지도

이 폴더는 Notes의 사용자용 동작을 검증하는 데 쓰는, 유지 관리되는 원천이다. 앱을 조작하기 전에 색인을 읽고, 해당 기능 파일을 절차서로 쓴다.

## 기본 전제 조건

- Notes를 `http://127.0.0.1:4173`에서 일회용 데이터 폴더로 기동한다.
- 동시에 도는 실행이 상태를 공유하지 않도록 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`를 설정한다.
- 제목이 `Quarterly plan`, `Grocery list`인 노트를 시드한다.
- `control-notes`와 `notes` CLI를 `PATH`에 둔다.
- `control-notes doctor`를 실행해 기대한 URL, 데이터 폴더, 빌드 리비전이 맞는지 확인한다.
- 이번 검증 실행이 시작하지 않은 인스턴스는 조작하지 않는다.

## 조작 규칙

- 절차의 전제 조건에 달리 적혀 있지 않으면 모든 절차를 기본 상태에서 시작한다.
- CSS 선택자나 DOM 위치보다 ARIA 역할과 접근 가능한 이름을 우선한다.
- 모든 명령을 문자 그대로 다룬다. 따옴표 안의 이름과 플래그를 바꾸지 않는다.
- 브라우저 동작은 `control-notes browser`로 실행한다.
- 터미널 동작은 `control-notes cli -- <command>`로 실행한다.
- 데이터를 바꾼 뒤에는 시드 데이터를 복원한다. 정리할 때 증명 산출물은 지우지 않는다.

## 증거와 건너뜀 보고

- 마지막 화면만이 아니라 사용자 동작과 그 결과 상태를 남긴다.
- UI 증거에는 ARIA 스냅샷과, 앱 이름이 보이는 스크린샷을 포함한다.
- CLI 증거에는 명령, stdout, stderr, 종료 코드를 포함한다.
- 데이터 변경 증거에는 저장된 값을 읽기 전용으로 한 번 더 본 화면을 포함한다.
- 모든 산출물에 기능 ID와 사용한 진입점을 기록한다.
- 도달할 수 없는 경로는 시도한 명령과 충족하지 못한 전제 조건과 함께 보고한다.
- 건너뛴 진입점을 다른 경로로 검증된 것으로 보고하지 않는다.

## 기능 파일 형식

기능 파일은 H1 제목과, 사용자에게 보이는 동작을 설명하는 문단 하나로 시작한다. 그다음 H2 섹션을 정확히 네 개, 아래 순서로 쓴다.

1. `하위 기능`은 짧은 ID와, 동작마다 한 줄을 나열한다.
2. `도달 방법 (사용자 시점)`은 사용자가 쓰는 진입점을 모두 나열한다.
3. `조작하기 (<도구>)`는 `전제 조건:`으로 시작하고, 사용자 동작마다 정확한 명령과 관찰 가능한 결과를 짝지은 이름표 붙은 항목을 쓴다.
4. `주의할 점`은 검증 실행을 낭비하게 하거나 무효로 만들 수 있는 함정을 나열한다.

구현 세부는 지도에 넣지 않는다. 사용자 경로, 안정적인 식별 수단, 필요한 상태, 명령, 관찰 가능한 증거만 적는다.

## 기능 목록

- [노트 만들기](./create-note.md)는 브라우저와 CLI에서의 생성, 취소, 저장 유지, 정리를 다룬다.
- [노트 검색](./search.md)은 툴바, 키보드, CLI 검색과 일치·결과 없음·검색어 지우기 상태를 다룬다.
